# Languages

Status: ready (own decisions). Roadmap item 4.1. Code: `scopeview-i18n`, settings window.

## Languages

English (`en-US`), Portuguese (`pt-BR`), Spanish (`es-ES`), French (`fr-FR`), German (`de-DE`) and
Italian (`it-IT`). Catalogs are Fluent files in `crates/i18n/locales/<code>/main.ftl`, embedded in
the binary. All text was written for this project. A native speaker should review each catalog;
until then they are marked as unreviewed in `progress.md`.

## Choosing the language

- Settings key `language`: one of the codes above, or absent to follow the operating system.
- On start, an absent or unknown value uses the OS locale (`pt_BR.UTF-8`, `de`, `fr-CA`, ...). Only the
  language part is matched, so `pt-PT` gives Portuguese. A locale we do not ship gives English.
- The settings window lists "System default" and each language under its own name (never
  translated). The change applies at once and is saved.

## Fallback

A key missing from the active catalog shows the English text, and a key missing from English shows
the key itself. Tests keep this from happening: every catalog must have exactly the English keys,
with the same `$variables` in each message, and most entries must differ from English.

## What is not translated

- Numbers in measurement labels and unit symbols keep `.` as the decimal separator and `mm` / `µm`,
  in every language. Photos and videos burn the labels in, and a saved image should not change with
  the language the app happened to run in.
- Format and codec names (JPEG, PNG, BMP, MJPEG, YUYV), device names and file names.
- Messages carrying counts are worded so they need no plural forms ("Calibrations: 2 of 10").
